# tinybar: discovery evidence for a focused native macOS usage monitor

## 1. What this project actually is, and how small it is

### Takeaway

Tinybar is genuinely native Swift/AppKit/SwiftUI, not a web wrapper. But its current release is **not just a minimal quota indicator**: five providers, browser credential fallback, persistent history, activity analytics, plan-value extrapolations, incident feeds, notifications and a Homebrew updater already make it a substantial product. Its boundaries are more useful to study than its name or performance claims. [Native entry point](https://github.com/ThiloReintjes/tinybar/blob/79cb32f7e71eacb9e8ce45508dd00fac26a08d53/Sources/Tinybar/main.swift#L1-L24), [application model](https://github.com/ThiloReintjes/tinybar/blob/79cb32f7e71eacb9e8ce45508dd00fac26a08d53/Sources/Tinybar/AppModel.swift#L18-L76), [feature inventory](https://github.com/ThiloReintjes/tinybar/blob/79cb32f7e71eacb9e8ce45508dd00fac26a08d53/README.md#L47-L65).

### Inferences

- “No dependencies” means **no third-party Swift packages**, not independence from changing external systems: provider endpoints and credential formats, official CLIs, browser databases/encryption, models.dev, GitHub, status pages and Homebrew are runtime/protocol dependencies. A new product could be smaller by omitting entire data products, not merely choosing Swift. [Manifest](https://github.com/ThiloReintjes/tinybar/blob/79cb32f7e71eacb9e8ce45508dd00fac26a08d53/Package.swift#L1-L24), [data-source table](https://github.com/ThiloReintjes/tinybar/blob/79cb32f7e71eacb9e8ce45508dd00fac26a08d53/README.md#L82-L97).
- Treat native implementation as a useful control over work/rendering, not proof of responsiveness. The present code is much broader than “a quota percentage in a menu bar.” [Feature list](https://github.com/ThiloReintjes/tinybar/blob/79cb32f7e71eacb9e8ce45508dd00fac26a08d53/README.md#L47-L65).

### Gaps

- No runtime launch, build, external script execution, benchmark, real provider call, installed-app inspection, credential read or browser-profile access was performed. This is static source research plus live GitHub metadata, not a usability or reliability certification.
- The user's providers, accounts, plans and machine requirements remain unspecified; none are inferred from this project's supported list.

## 2. Provider collection: auth → source → displayed information

### Takeaway

Tinybar separates provider-reported quota windows from **local logged token counts repriced at current API rates**. That separation is essential: local tokens/costs are neither the provider's subscription meter nor a bill, and cross-device/browser/account usage can make the two diverge. Provider protocol details below are **observations of Tinybar's implementation**, not independently authenticated endpoint contracts. [Limit model](https://github.com/ThiloReintjes/tinybar/blob/79cb32f7e71eacb9e8ce45508dd00fac26a08d53/Sources/TinybarCore/Models.swift#L58-L83), [in-app explanation](https://github.com/ThiloReintjes/tinybar/blob/79cb32f7e71eacb9e8ce45508dd00fac26a08d53/Sources/Tinybar/CountingNotes.swift#L14-L35).

### Cited Findings

#### Claude

- **Auth:** first readable `.credentials.json` from `CLAUDE_CONFIG_DIR` (supports comma-separated directories), otherwise existing `~/.claude` / `~/.config/claude`; then Keychain service `Claude Code-credentials` read via `/usr/bin/security find-generic-password … -w`. Parses `claudeAiOauth.accessToken`, millisecond `expiresAt`, subscription type/tier. Expired credentials are rejected; Tinybar has no refresh-token write flow. File precedence means the first readable credential file wins, even if another directory/Keychain represents a different valid account. [Paths](https://github.com/ThiloReintjes/tinybar/blob/79cb32f7e71eacb9e8ce45508dd00fac26a08d53/Sources/TinybarCore/Paths.swift#L27-L41), [credential loading](https://github.com/ThiloReintjes/tinybar/blob/79cb32f7e71eacb9e8ce45508dd00fac26a08d53/Sources/TinybarCore/Claude/ClaudeCredentials.swift#L34-L95), [fetch/fallback](https://github.com/ThiloReintjes/tinybar/blob/79cb32f7e71eacb9e8ce45508dd00fac26a08d53/Sources/TinybarCore/Claude/ClaudeProvider.swift#L19-L31).
- **Network/protocol:** GET `https://api.anthropic.com/api/oauth/usage`, bearer token, beta header `oauth-2025-04-20`, User-Agent `claude-code/<installed version>` (fallback `2.1.0`). Adds `?cedar_ember=1` for banked reset grants; retries without it on 400/403. Maps `five_hour`, `seven_day`, newer scoped `limits` or legacy Opus/Sonnet weekly windows; percentages already 0–100, ISO reset dates, hardcoded 5h/7d durations. Extra-usage cents divide by 100; grants count only eligible/unpaused/current resets, never decode redemption handles. [Requests and compatibility retry](https://github.com/ThiloReintjes/tinybar/blob/79cb32f7e71eacb9e8ce45508dd00fac26a08d53/Sources/TinybarCore/Claude/ClaudeUsageAPI.swift#L136-L173), [mapping](https://github.com/ThiloReintjes/tinybar/blob/79cb32f7e71eacb9e8ce45508dd00fac26a08d53/Sources/TinybarCore/Claude/ClaudeUsageAPI.swift#L177-L222), [grants](https://github.com/ThiloReintjes/tinybar/blob/79cb32f7e71eacb9e8ce45508dd00fac26a08d53/Sources/TinybarCore/Claude/ClaudeUsageAPI.swift#L42-L79).
- **Browser fallback:** only on missing/expired login and explicit per-provider opt-in. Reads `claude.ai` `sessionKey`, GETs `/api/organizations`, chooses first chat-capable organization (fallback first non-API-only, then first), then `/api/organizations/<uuid>/usage`; optional `/overage_spend_limit` cannot hide primary limits on failure. Browser snapshot has no plan metadata. [Provider](https://github.com/ThiloReintjes/tinybar/blob/79cb32f7e71eacb9e8ce45508dd00fac26a08d53/Sources/TinybarCore/Claude/ClaudeProvider.swift#L19-L31), [web API](https://github.com/ThiloReintjes/tinybar/blob/79cb32f7e71eacb9e8ce45508dd00fac26a08d53/Sources/TinybarCore/Claude/ClaudeWebAPI.swift#L29-L72).
- **Local usage:** `<Claude config dirs>/projects/**/*.jsonl`; assistant `message.usage` input/output/cache creation/cache read counts, skipping synthetic responses. Streaming and copied/forked transcripts repeat message IDs, so store deduplicates globally and replaces earlier token contributions with more complete copies; identity retention is bounded (ADR says 90 days). These are local log observations, not complete account usage. [Roots](https://github.com/ThiloReintjes/tinybar/blob/79cb32f7e71eacb9e8ce45508dd00fac26a08d53/Sources/TinybarCore/Usage/UsageStore.swift#L216-L221), [parser](https://github.com/ThiloReintjes/tinybar/blob/79cb32f7e71eacb9e8ce45508dd00fac26a08d53/Sources/TinybarCore/Usage/ClaudeLogParser.swift#L3-L49), [replacement](https://github.com/ThiloReintjes/tinybar/blob/79cb32f7e71eacb9e8ce45508dd00fac26a08d53/Sources/TinybarCore/Usage/UsageStore.swift#L537-L568), [retention decision](https://github.com/ThiloReintjes/tinybar/blob/79cb32f7e71eacb9e8ce45508dd00fac26a08d53/docs/adr/0003-daily-aggregates.md#L1-L11).

#### Codex

- **Auth/source order:** `CODEX_HOME/auth.json` (default `~/.codex/auth.json`); OAuth access token plus account ID from explicit field or decoded ID-token JWT. GET `https://chatgpt.com/backend-api/wham/usage`, bearer token and optional `ChatGPT-Account-Id`. Separately requests `/wham/rate-limit-reset-credits` in parallel; failure of that optional extra does not discard primary usage. Maps primary/secondary and named additional/model windows from provider duration seconds and Unix reset timestamps, plus plan, credits and reset coupons. [Credentials](https://github.com/ThiloReintjes/tinybar/blob/79cb32f7e71eacb9e8ce45508dd00fac26a08d53/Sources/TinybarCore/Codex/CodexCredentials.swift#L9-L47), [requests](https://github.com/ThiloReintjes/tinybar/blob/79cb32f7e71eacb9e8ce45508dd00fac26a08d53/Sources/TinybarCore/Codex/CodexUsageAPI.swift#L114-L157), [mapping](https://github.com/ThiloReintjes/tinybar/blob/79cb32f7e71eacb9e8ce45508dd00fac26a08d53/Sources/TinybarCore/Codex/CodexUsageAPI.swift#L172-L207).
- **CLI fallback:** only for missing/expired direct login, not network/rate errors; executes located `codex -s read-only -a never app-server`, sends JSON-RPC `initialize`, `initialized`, `account/rateLimits/read`, then kills/reaps child. 15-second watchdog; output bounded to 1 MiB. This lets the CLI handle/refresh its own login: “Tinybar doesn't refresh tokens” does **not** mean no child can refresh them. Failed CLI fallback is swallowed before trying opt-in browser or reporting the previous login error. [Selection](https://github.com/ThiloReintjes/tinybar/blob/79cb32f7e71eacb9e8ce45508dd00fac26a08d53/Sources/TinybarCore/Codex/CodexProvider.swift#L19-L52), [execution/watchdog](https://github.com/ThiloReintjes/tinybar/blob/79cb32f7e71eacb9e8ce45508dd00fac26a08d53/Sources/TinybarCore/Codex/CodexAppServer.swift#L101-L142), [RPC/read limit](https://github.com/ThiloReintjes/tinybar/blob/79cb32f7e71eacb9e8ce45508dd00fac26a08d53/Sources/TinybarCore/Codex/CodexAppServer.swift#L151-L205).
- **Browser:** opt-in `chatgpt.com` session cookie `__Secure-next-auth.session-token` (including chunks); GET `/api/auth/session` returns short-lived `accessToken` and optional `account.id`; then same usage endpoints. Rejects session response with auth error instead of refreshing it. Only auth/callback cookies are transmitted, not the whole domain jar. [Session exchange](https://github.com/ThiloReintjes/tinybar/blob/79cb32f7e71eacb9e8ce45508dd00fac26a08d53/Sources/TinybarCore/Codex/ChatGPTWebSession.swift#L3-L33).
- **Local usage:** `sessions` and `archived_sessions`; incremental rollout parser tracks model/cwd from context, consumes `event_msg/token_count` `last_token_usage`, suppresses repeated cumulative totals and fork replay by timestamp/watermark. Input subtracts cached and cache-write input; output uses `output_tokens` without separately adding reasoning. Compact JSON markers and early-line/prefix assumptions are visible in fast paths. [Roots](https://github.com/ThiloReintjes/tinybar/blob/79cb32f7e71eacb9e8ce45508dd00fac26a08d53/Sources/TinybarCore/Usage/UsageStore.swift#L216-L219), [parser and replay](https://github.com/ThiloReintjes/tinybar/blob/79cb32f7e71eacb9e8ce45508dd00fac26a08d53/Sources/TinybarCore/Usage/CodexLogParser.swift#L41-L177).
- **History coverage limit:** the in-app counting note explicitly says compressed older Codex logs cannot yet be read, so days can retain previously collected tokens but have little activity. This is a documented omission, not proof that a blank history means zero use. [Coverage explanation](https://github.com/ThiloReintjes/tinybar/blob/79cb32f7e71eacb9e8ce45508dd00fac26a08d53/Sources/Tinybar/CountingNotes.swift#L48-L60).

#### Gemini (specifically Antigravity CLI quotas)

- No Google credentials parsed by Tinybar. Detects `agy` in a short fixed path list plus `~/.gemini/antigravity-cli`; executes **`agy -p /usage --output-format json --log-file /dev/null`** in a fresh empty temporary cwd, closed stdin, detached utility task. 45-second kill watchdog and 1 MiB output bound. The code comments describe this as a built-in command, not a model turn; we did not verify installed CLI behavior. CLI can refresh its own login. [Detection/fetch](https://github.com/ThiloReintjes/tinybar/blob/79cb32f7e71eacb9e8ce45508dd00fac26a08d53/Sources/TinybarCore/Gemini/GeminiProvider.swift#L3-L37), [process](https://github.com/ThiloReintjes/tinybar/blob/79cb32f7e71eacb9e8ce45508dd00fac26a08d53/Sources/TinybarCore/Gemini/GeminiProvider.swift#L124-L172).
- Parses `status=SUCCESS`, `command.name=usage`, `groups[].buckets[]`: remaining fraction → used percent; `5h`/`weekly` → known duration; reset ISO timestamp. Group whose name starts “gemini” is account-wide; others are labelled “Claude & GPT” model-specific. No plan or token/cost history. This is not evidence of generic Gemini CLI/API billing support; group strings and CLI JSON shape are compatibility assumptions. [Report/mapping](https://github.com/ThiloReintjes/tinybar/blob/79cb32f7e71eacb9e8ce45508dd00fac26a08d53/Sources/TinybarCore/Gemini/GeminiProvider.swift#L42-L121), [limits-only history boundary](https://github.com/ThiloReintjes/tinybar/blob/79cb32f7e71eacb9e8ce45508dd00fac26a08d53/Sources/Tinybar/CountingNotes.swift#L20-L24).

#### Cursor

- Reads `~/Library/Application Support/Cursor/User/globalStorage/state.vscdb`, `ItemTable` key `cursorAuth/accessToken`, with UTF-8/UTF-16/quoted-string handling. Parses JWT expiry (rejects within 60 seconds), extracts user ID from `sub`, synthesizes `WorkosCursorSessionToken=<userID>%3A%3A<token>`. GET `https://cursor.com/api/usage-summary`. Missing/expired app login falls back to browser `cursor.com` then `www.cursor.com` cookie. [Auth and selection](https://github.com/ThiloReintjes/tinybar/blob/79cb32f7e71eacb9e8ce45508dd00fac26a08d53/Sources/TinybarCore/Cursor/CursorProvider.swift#L16-L112), [request](https://github.com/ThiloReintjes/tinybar/blob/79cb32f7e71eacb9e8ce45508dd00fac26a08d53/Sources/TinybarCore/Cursor/CursorUsageAPI.swift#L3-L64).
- Billing cycle from start/end dates; uses total percent, otherwise used/limit cents, otherwise individual overall, otherwise team pooled cap. Optional Auto/API model percentages; unlimited suppresses windows. On-demand cents become USD spend. No local token/activity history. A team-pool fallback is not the same unit/scope as a personal cap, though both render as “Billing cycle.” [Mapping](https://github.com/ThiloReintjes/tinybar/blob/79cb32f7e71eacb9e8ce45508dd00fac26a08d53/Sources/TinybarCore/Cursor/CursorUsageAPI.swift#L69-L112), [history boundary](https://github.com/ThiloReintjes/tinybar/blob/79cb32f7e71eacb9e8ce45508dd00fac26a08d53/Sources/Tinybar/CountingNotes.swift#L20-L24).
- **Consent exception:** Cursor has no separate browser-fallback toggle. Enabling Cursor is treated as consent; automatically enabled when an app token is present, even if expired. Thus “browser fallback off by default” is not a universal behavior after an auto-enabled Cursor login expires. [Provider logic](https://github.com/ThiloReintjes/tinybar/blob/79cb32f7e71eacb9e8ce45508dd00fac26a08d53/Sources/TinybarCore/Cursor/CursorProvider.swift#L16-L43), [ADR](https://github.com/ThiloReintjes/tinybar/blob/79cb32f7e71eacb9e8ce45508dd00fac26a08d53/docs/adr/0005-browser-cookie-consent.md#L1-L7).

#### OpenCode Go

- Reads OpenCode data under absolute `XDG_DATA_HOME` or `~/.local/share/opencode`, honoring `OPENCODE_DB`. 2.x `credential` table prioritizes `opencode-go` over Console `opencode`, then active/newest credential. Legacy 1.x uses `auth.json`; avoids resurrecting stale auth.json after 2.x logout. Supports key/api or unexpired OAuth access (not refresh); optional metadata org ID/header. Auto-enabled only with a Go integration credential; Console login is opt-in. [Location/selection](https://github.com/ThiloReintjes/tinybar/blob/79cb32f7e71eacb9e8ce45508dd00fac26a08d53/Sources/TinybarCore/OpenCode/OpenCodeProvider.swift#L19-L95), [login validation](https://github.com/ThiloReintjes/tinybar/blob/79cb32f7e71eacb9e8ce45508dd00fac26a08d53/Sources/TinybarCore/OpenCode/OpenCodeProvider.swift#L99-L157).
- GET `<allowed origin>/zen/go/v1/usage`, bearer token, optional `x-opencode-org-id`; origin restricted to HTTPS opencode.ai/subdomains or localhost (HTTP permitted locally). Maps `rolling`, `weekly`, `monthly` percent/reset; `rate-limited` status forces used=100 regardless of reported percent. Rolling assumed 5h, weekly 7d, monthly duration inferred as preceding calendar month. No browser fallback, Zen balance, Console budget, activity analytics or Go plan-value extrapolation. [Request/mapping](https://github.com/ThiloReintjes/tinybar/blob/79cb32f7e71eacb9e8ce45508dd00fac26a08d53/Sources/TinybarCore/OpenCode/OpenCodeUsageAPI.swift#L27-L86), [deliberate scope](https://github.com/ThiloReintjes/tinybar/blob/79cb32f7e71eacb9e8ce45508dd00fac26a08d53/docs/adr/0009-opencode-go-only.md#L1-L13).
- Local DB history reads completed assistant/compaction rows from v1/v2 schemas, **only providerID `opencode-go`**. Adds reasoning to output (unlike Codex field semantics); deduplicates on millisecond time+model+token tuple, not message ID because forks/migrations copy IDs differently. Reads with 10-minute overlap and persistent watermark, skips unchanged DB+WAL stamps, holds watermark if snapshot was unsettled, retries unreadable schema. Tuple collisions and rows committed over 10 minutes late are accepted/possible incompleteness boundaries. [Queries/tokens/dedup](https://github.com/ThiloReintjes/tinybar/blob/79cb32f7e71eacb9e8ce45508dd00fac26a08d53/Sources/TinybarCore/OpenCode/OpenCodeHistory.swift#L19-L82), [incremental DB ingestion](https://github.com/ThiloReintjes/tinybar/blob/79cb32f7e71eacb9e8ce45508dd00fac26a08d53/Sources/TinybarCore/Usage/UsageStore.swift#L272-L321), [explicit collision tradeoff](https://github.com/ThiloReintjes/tinybar/blob/79cb32f7e71eacb9e8ce45508dd00fac26a08d53/docs/adr/0009-opencode-go-only.md#L9-L13).
- **Critical validation limit:** maintainer explicitly says no real paid Go subscription was tested. Compatibility was tested using real OpenCode CLIs against a local mock; Go-key endpoint acceptance came from CodexBar, and the real 403 body was only known from upstream tests. Do not promote this source adapter to “production-proven.” [ADR disclosure](https://github.com/ThiloReintjes/tinybar/blob/79cb32f7e71eacb9e8ce45508dd00fac26a08d53/docs/adr/0009-opencode-go-only.md#L15-L31).

#### Common interpretation, pricing and security

- Quotas and logged usage stay different: history aggregates per local day/provider/model/project and survives deleted logs; Today/7d/30d are local calendar ranges, **not quota reset windows**. Prices are current models.dev rates by provider/model/cache/context tier, not recorded invoice rates. Missing prices produce dashes or partial totals with `+`; cached prices survive fetch failure. Pricing failure retries only after 24h, including across restarts. [Aggregation/ranges](https://github.com/ThiloReintjes/tinybar/blob/79cb32f7e71eacb9e8ce45508dd00fac26a08d53/Sources/TinybarCore/Usage/UsageSummary.swift#L3-L106), [pricing/missing models](https://github.com/ThiloReintjes/tinybar/blob/79cb32f7e71eacb9e8ce45508dd00fac26a08d53/Sources/TinybarCore/Pricing/Pricing.swift#L3-L100), [price scheduling](https://github.com/ThiloReintjes/tinybar/blob/79cb32f7e71eacb9e8ce45508dd00fac26a08d53/Sources/TinybarCore/Pricing/Pricing.swift#L154-L194), [UI labelling](https://github.com/ThiloReintjes/tinybar/blob/79cb32f7e71eacb9e8ce45508dd00fac26a08d53/Sources/Tinybar/PopoverView.swift#L681-L711).
- Plans are **another estimate**: observed logged API-equivalent cost divided by observed weekly percent used, median across measured windows, with 10%-used minimum, hardcoded US subscription prices and hand-copied Artificial Analysis scores/task costs. Neither account billing nor a benchmark of the user's work. [Formula/prices/benchmark metadata](https://github.com/ThiloReintjes/tinybar/blob/79cb32f7e71eacb9e8ce45508dd00fac26a08d53/Sources/TinybarCore/Usage/PlanValue.swift#L27-L81), [extrapolation](https://github.com/ThiloReintjes/tinybar/blob/79cb32f7e71eacb9e8ce45508dd00fac26a08d53/Sources/TinybarCore/Usage/PlanValue.swift#L145-L165).
- Credentials are sent with ephemeral URLSession, no persistent cookie jar/disk URL cache. Shared HTTP blocks credential-bearing redirects across scheme/host/port boundaries; maps 401/403 to loginExpired (unless specially handled), 429 to Retry-After seconds/HTTP date. Error bodies are generally not exposed. This is deliberate defensive code, not an independent security audit. [Session config](https://github.com/ThiloReintjes/tinybar/blob/79cb32f7e71eacb9e8ce45508dd00fac26a08d53/Sources/TinybarCore/Codex/CodexProvider.swift#L56-L65), [HTTP](https://github.com/ThiloReintjes/tinybar/blob/79cb32f7e71eacb9e8ce45508dd00fac26a08d53/Sources/TinybarCore/HTTP.swift#L11-L72).
- Browser scanner tries Chrome, Arc, Dia, Brave, Edge, Comet, Firefox in fixed order and sorted profiles; returns first matching cookie set, **not a user-selected account/profile**. Chromium assumes v10 AES-CBC cookies/PBKDF2 Safe Storage key, handles newer host-hash prefix; key or denial cached for process lifetime. Firefox plaintext; Safari omitted rather than requiring Full Disk Access. [Discovery/selection](https://github.com/ThiloReintjes/tinybar/blob/79cb32f7e71eacb9e8ce45508dd00fac26a08d53/Sources/TinybarCore/Cookies/BrowserCookies.swift#L5-L88), [decryption/key cache](https://github.com/ThiloReintjes/tinybar/blob/79cb32f7e71eacb9e8ce45508dd00fac26a08d53/Sources/TinybarCore/Cookies/BrowserCookies.swift#L146-L204).
- **Read-only originals is not zero disk copying:** shared credential database helper opens immutable when no WAL; with WAL, copies the **whole database and WAL** into a 0700 temp directory, reads privately and deletes afterward. Avoids SQLite sidecar writes to browser/Cursor/OpenCode originals, but temporarily duplicates sensitive DB contents. No sandbox entitlement is added by the inspected bundle-signing script; it is a regular desktop process with user-level file access, not an App Store sandbox design. [Database snapshots](https://github.com/ThiloReintjes/tinybar/blob/79cb32f7e71eacb9e8ce45508dd00fac26a08d53/Sources/TinybarCore/Cookies/BrowserCookies.swift#L231-L259), [signing](https://github.com/ThiloReintjes/tinybar/blob/79cb32f7e71eacb9e8ce45508dd00fac26a08d53/Scripts/build-app.sh#L14-L25).
- Local `usage.sqlite` contains totals, file/project paths, IDs, activity counters and response timing, not full prompts/responses/commands/diffs. It is ordinary SQLite WAL storage, not an encrypted history vault. Source/provider attribution is coarse: Claude transcripts with GPT/o1/o3/o4/Codex model names are assigned to `.codex`, otherwise `.claude`, regardless of actual subscription/payment route. [Storage policy](https://github.com/ThiloReintjes/tinybar/blob/79cb32f7e71eacb9e8ce45508dd00fac26a08d53/SECURITY.md#L41-L46), [SQLite](https://github.com/ThiloReintjes/tinybar/blob/79cb32f7e71eacb9e8ce45508dd00fac26a08d53/Sources/TinybarCore/Usage/SQLite.swift#L4-L17), [routing heuristic](https://github.com/ThiloReintjes/tinybar/blob/79cb32f7e71eacb9e8ce45508dd00fac26a08d53/Sources/TinybarCore/Usage/ClaudeLogParser.swift#L298-L304).

### Inferences

- **High-value reusable protocol discoveries:** source-specific units are essential (Cursor percentages vs cents, Claude cents, Gemini remaining fraction, different reasoning-token semantics), as are preserving provider-supplied durations/resets and distinguishing optional endpoint failure from primary failure. These details need fresh, provider-specific validation before reuse; the small adapter does not make an undocumented protocol stable. [Claude mapping](https://github.com/ThiloReintjes/tinybar/blob/79cb32f7e71eacb9e8ce45508dd00fac26a08d53/Sources/TinybarCore/Claude/ClaudeUsageAPI.swift#L177-L222), [Cursor mapping](https://github.com/ThiloReintjes/tinybar/blob/79cb32f7e71eacb9e8ce45508dd00fac26a08d53/Sources/TinybarCore/Cursor/CursorUsageAPI.swift#L30-L37), [OpenCode output](https://github.com/ThiloReintjes/tinybar/blob/79cb32f7e71eacb9e8ce45508dd00fac26a08d53/Sources/TinybarCore/OpenCode/OpenCodeHistory.swift#L72-L82).
- **Account mismatch risk:** browser fallback can silently represent a different account from CLI/history; Claude organization choice and first-browser-profile choice amplify this. Snapshots carry provider/plan/source/time, but no account identity; no source hint rendering was found in app UI (CLI explicitly prints it). A new monitor should establish provenance/account confidence rather than treating all successful fetches as equivalent. [Snapshot fields](https://github.com/ThiloReintjes/tinybar/blob/79cb32f7e71eacb9e8ce45508dd00fac26a08d53/Sources/TinybarCore/Models.swift#L158-L187), [browser selection](https://github.com/ThiloReintjes/tinybar/blob/79cb32f7e71eacb9e8ce45508dd00fac26a08d53/Sources/TinybarCore/Cookies/BrowserCookies.swift#L36-L51), [CLI provenance](https://github.com/ThiloReintjes/tinybar/blob/79cb32f7e71eacb9e8ce45508dd00fac26a08d53/Sources/tinybar-cli/main.swift#L24-L30).
- **Brittle surfaces to budget for:** provider-private endpoints/beta headers, schema-tolerant optional decoding, credential files/Keychain service names, fixed CLI paths and report/RPC shapes, browser encryption, JSON formatting/prefix sniffing, OpenCode table migrations, status-page component names. “No web scraping” would not eliminate these maintenance costs. [Claude wire decoder](https://github.com/ThiloReintjes/tinybar/blob/79cb32f7e71eacb9e8ce45508dd00fac26a08d53/Sources/TinybarCore/Claude/ClaudeUsageAPI.swift#L30-L38), [Codex parser fast paths](https://github.com/ThiloReintjes/tinybar/blob/79cb32f7e71eacb9e8ce45508dd00fac26a08d53/Sources/TinybarCore/Usage/CodexLogParser.swift#L96-L138), [status source selection](https://github.com/ThiloReintjes/tinybar/blob/79cb32f7e71eacb9e8ce45508dd00fac26a08d53/Sources/TinybarCore/Status/Incident.swift#L64-L102).
- **Permissive parsing tradeoff:** Claude/Codex optional field decoders can turn an incompatible but syntactically valid response into a successful snapshot with no windows, clearing an earlier error. UI says “No limits reported”; it does not distinguish valid unlimited/no-limits from a changed schema. OpenCode explicitly rejects an empty window list. This is an inferred failure mode, not a reproduced outage. [Claude decoding](https://github.com/ThiloReintjes/tinybar/blob/79cb32f7e71eacb9e8ce45508dd00fac26a08d53/Sources/TinybarCore/Claude/ClaudeUsageAPI.swift#L30-L38), [Codex decoding](https://github.com/ThiloReintjes/tinybar/blob/79cb32f7e71eacb9e8ce45508dd00fac26a08d53/Sources/TinybarCore/Codex/CodexUsageAPI.swift#L22-L45), [UI](https://github.com/ThiloReintjes/tinybar/blob/79cb32f7e71eacb9e8ce45508dd00fac26a08d53/Sources/Tinybar/PopoverView.swift#L329-L335), [OpenCode guard](https://github.com/ThiloReintjes/tinybar/blob/79cb32f7e71eacb9e8ce45508dd00fac26a08d53/Sources/TinybarCore/OpenCode/OpenCodeUsageAPI.swift#L72-L78).
- **Plan-value limitations:** local-only history divided by account-wide quota use is not robust when other devices/web usage/accounts contribute, and model-prefix attribution need not match payment source. Current-rate repricing also changes past dollar equivalents when prices change. These are reasons to question whether this feature helps the user's decision, not reasons to assume it is required. [Formula](https://github.com/ThiloReintjes/tinybar/blob/79cb32f7e71eacb9e8ce45508dd00fac26a08d53/Sources/TinybarCore/Usage/PlanValue.swift#L145-L165), [pricing at display time](https://github.com/ThiloReintjes/tinybar/blob/79cb32f7e71eacb9e8ce45508dd00fac26a08d53/Sources/TinybarCore/Usage/UsageStore.swift#L14-L19).

### Gaps

- No endpoint was exercised or independently checked against provider documentation/paid accounts. Especially do not repeat the Gemini file's historical comments about Google's service changes as independently established facts; this research established only the implemented `agy` path.
- Undocumented auth access does not establish provider policy approval or eliminate account risk. The project's ADR claims lower flagging risk, but provides no measured guarantee. [Read-only ADR](https://github.com/ThiloReintjes/tinybar/blob/79cb32f7e71eacb9e8ce45508dd00fac26a08d53/docs/adr/0001-read-only-credentials.md#L3-L7).

## 3. Refresh, reliability, omitted complexity and lessons for discussion

### Takeaway

The useful simplicity is **bounded work and explicit limits**: one slow poll cadence, event-driven dirty paths, incremental parsing, native change-driven drawing, read-only credential reuse and a single state model. The omissions are mixed: no account management or refresh ownership can be acceptable scope choices, while weak freshness/provenance/error reporting would undermine the very trustworthy, low-friction monitor the user wants. None of this proves Tinybar faster than CodexBar. [Refresh lifecycle](https://github.com/ThiloReintjes/tinybar/blob/79cb32f7e71eacb9e8ce45508dd00fac26a08d53/Sources/Tinybar/AppModel.swift#L80-L198), [incremental log watcher](https://github.com/ThiloReintjes/tinybar/blob/79cb32f7e71eacb9e8ce45508dd00fac26a08d53/Sources/TinybarCore/Usage/LogWatcher.swift#L4-L17), [change-driven drawing](https://github.com/ThiloReintjes/tinybar/blob/79cb32f7e71eacb9e8ce45508dd00fac26a08d53/Sources/Tinybar/StatusItemController.swift#L56-L96).

### Cited Findings

#### Refresh/concurrency/main thread

- Five-minute main-runloop timer with 30s tolerance; startup refresh; open/manual refresh throttled per provider to one minute. Concurrent task group fetches enabled providers and applies each completed result independently. Global `isFetching` prevents overlapping poll sequences; force/wake can queue a pending pass; 429 backoff is respected even for forced refresh and survives provider off/on in memory. No configurable poll interval. [Scheduling](https://github.com/ThiloReintjes/tinybar/blob/79cb32f7e71eacb9e8ce45508dd00fac26a08d53/Sources/Tinybar/AppModel.swift#L48-L57), [refresh control](https://github.com/ThiloReintjes/tinybar/blob/79cb32f7e71eacb9e8ce45508dd00fac26a08d53/Sources/Tinybar/AppModel.swift#L92-L198), [application/backoff](https://github.com/ThiloReintjes/tinybar/blob/79cb32f7e71eacb9e8ce45508dd00fac26a08d53/Sources/Tinybar/AppModel.swift#L230-L249).
- Sleeps/locks stop the poll timer; wake/unlock reschedules and requests refresh. Already-running fetches/imports are **not cancelled** by pause; stage boundaries guard before subsequent work. This is pause-new-work behavior, not zero work during sleep/lock. [Lifecycle/pause](https://github.com/ThiloReintjes/tinybar/blob/79cb32f7e71eacb9e8ce45508dd00fac26a08d53/Sources/Tinybar/AppModel.swift#L102-L129), [between-stage guards](https://github.com/ThiloReintjes/tinybar/blob/79cb32f7e71eacb9e8ce45508dd00fac26a08d53/Sources/Tinybar/AppModel.swift#L179-L198), [import guards](https://github.com/ThiloReintjes/tinybar/blob/79cb32f7e71eacb9e8ce45508dd00fac26a08d53/Sources/Tinybar/AppModel.swift#L252-L301).
- FSEvents utility queue collects dirty JSONL paths with 10s latency; ingestion happens on refresh, not each event. Dropped/directory/root events or unavailable stream trigger a full walk. Store actor reads appended bytes using saved file stamps/offset/parser state; file rewrite/replay handling, batching and transactions protect against duplicate counts; >1 MiB lines are skipped, partial trailing lines retained for next read. [Watcher](https://github.com/ThiloReintjes/tinybar/blob/79cb32f7e71eacb9e8ce45508dd00fac26a08d53/Sources/TinybarCore/Usage/LogWatcher.swift#L20-L44), [drain/recovery](https://github.com/ThiloReintjes/tinybar/blob/79cb32f7e71eacb9e8ce45508dd00fac26a08d53/Sources/TinybarCore/Usage/LogWatcher.swift#L71-L96), [ingestion](https://github.com/ThiloReintjes/tinybar/blob/79cb32f7e71eacb9e8ce45508dd00fac26a08d53/Sources/TinybarCore/Usage/UsageStore.swift#L344-L427), [bounded reader](https://github.com/ThiloReintjes/tinybar/blob/79cb32f7e71eacb9e8ce45508dd00fac26a08d53/Sources/TinybarCore/Usage/UsageStore.swift#L1112-L1189).
- Heavy initial history/backfills use a child copy of Tinybar and progress pipe; child exits after work, reclaiming process allocations. Later provider polls do not wait on a previously running usage task. Failed initial import does not fall back to expensive in-process import; retries on relaunch. Incremental ingest errors retain dirty paths for next poll. [Child](https://github.com/ThiloReintjes/tinybar/blob/79cb32f7e71eacb9e8ce45508dd00fac26a08d53/Sources/Tinybar/HistoryImport.swift#L4-L85), [shared task](https://github.com/ThiloReintjes/tinybar/blob/79cb32f7e71eacb9e8ce45508dd00fac26a08d53/Sources/Tinybar/AppModel.swift#L143-L198), [failure handling](https://github.com/ThiloReintjes/tinybar/blob/79cb32f7e71eacb9e8ce45508dd00fac26a08d53/Sources/Tinybar/AppModel.swift#L252-L296).
- `AppModel` and UI are MainActor; blocking CLI RPC/agy calls are explicitly detached utility tasks; SQLite ingestion lives in a separate actor. However **startup is not wholly nonblocking**: MainActor initializer synchronously creates/migrates store and invokes configured checks; Claude's presence check waits for `/usr/bin/security` with no watchdog, and Cursor/OpenCode checks can synchronously snapshot DBs. Summary/plan/stat transformations after awaits run on MainActor. These are source-level potential stalls, not measured lag. [Initializer](https://github.com/ThiloReintjes/tinybar/blob/79cb32f7e71eacb9e8ce45508dd00fac26a08d53/Sources/Tinybar/AppModel.swift#L16-L75), [presence process](https://github.com/ThiloReintjes/tinybar/blob/79cb32f7e71eacb9e8ce45508dd00fac26a08d53/Sources/TinybarCore/Claude/ClaudeCredentials.swift#L36-L46), [store init](https://github.com/ThiloReintjes/tinybar/blob/79cb32f7e71eacb9e8ce45508dd00fac26a08d53/Sources/TinybarCore/Usage/UsageStore.swift#L37-L49), [summary transforms](https://github.com/ThiloReintjes/tinybar/blob/79cb32f7e71eacb9e8ce45508dd00fac26a08d53/Sources/Tinybar/AppModel.swift#L307-L374).
- Menu item only redraws when integer remaining percent/provider/stale/appearance/settings/incident key changes; no status-item timer/animation. Popover animations exist, but no recurring countdown timer/TimelineView was found. Reset/countdown strings use `Date()` at view evaluation. A continuously open popover may show old countdown text until another observed change rerenders it; this is inferred from static text rendering, not a runtime reproduction. [Render key](https://github.com/ThiloReintjes/tinybar/blob/79cb32f7e71eacb9e8ce45508dd00fac26a08d53/Sources/Tinybar/StatusItemController.swift#L5-L22), [redraw guard](https://github.com/ThiloReintjes/tinybar/blob/79cb32f7e71eacb9e8ce45508dd00fac26a08d53/Sources/Tinybar/StatusItemController.swift#L65-L96), [countdown display](https://github.com/ThiloReintjes/tinybar/blob/79cb32f7e71eacb9e8ce45508dd00fac26a08d53/Sources/Tinybar/PopoverView.swift#L547-L575), [formatter](https://github.com/ThiloReintjes/tinybar/blob/79cb32f7e71eacb9e8ce45508dd00fac26a08d53/Sources/TinybarCore/Usage/UsageSummary.swift#L152-L159).

#### Errors/freshness/security/update burden

- Primary failure preserves last snapshot and sets an error; UI dims old numbers, removes forecast and explicitly says when retained numbers were fetched. But `isStale` is **only `error != nil`**, with no age threshold: an old successful snapshot during lock/sleep remains nominally fresh until a failed next attempt. `lastUpdated` is a global history-task completion timestamp, not proof that each provider was successfully fetched; footer says “Checked,” and update pill can replace that footer time. [State](https://github.com/ThiloReintjes/tinybar/blob/79cb32f7e71eacb9e8ce45508dd00fac26a08d53/Sources/Tinybar/AppModel.swift#L6-L14), [application/history time](https://github.com/ThiloReintjes/tinybar/blob/79cb32f7e71eacb9e8ce45508dd00fac26a08d53/Sources/Tinybar/AppModel.swift#L191-L198), [stale detail](https://github.com/ThiloReintjes/tinybar/blob/79cb32f7e71eacb9e8ce45508dd00fac26a08d53/Sources/Tinybar/PopoverView.swift#L510-L525), [footer](https://github.com/ThiloReintjes/tinybar/blob/79cb32f7e71eacb9e8ce45508dd00fac26a08d53/Sources/Tinybar/PopoverView.swift#L732-L752).
- Local usage failures are less visible: failed store creation is `try?`; ingest failure keeps paths but no UI error; failed daily query replaces rows with `[]`; `lastUpdated` can still advance. OpenCode unreadable schema contributes nothing and retries. **Disabling a provider does not disable history ingestion**: ingestAll always reads both log sources and checks OpenCode, and rebuildUsage uses all stored rows regardless of enabled quota providers. A subscription toggle is not a collection/privacy toggle. [Store init](https://github.com/ThiloReintjes/tinybar/blob/79cb32f7e71eacb9e8ce45508dd00fac26a08d53/Sources/Tinybar/AppModel.swift#L69-L75), [usage errors](https://github.com/ThiloReintjes/tinybar/blob/79cb32f7e71eacb9e8ce45508dd00fac26a08d53/Sources/Tinybar/AppModel.swift#L279-L304), [all-source ingestion](https://github.com/ThiloReintjes/tinybar/blob/79cb32f7e71eacb9e8ce45508dd00fac26a08d53/Sources/TinybarCore/Usage/UsageStore.swift#L234-L251), [unfiltered summaries](https://github.com/ThiloReintjes/tinybar/blob/79cb32f7e71eacb9e8ce45508dd00fac26a08d53/Sources/Tinybar/AppModel.swift#L331-L344).
- Status pages add 1–2 unauthenticated GETs per enabled feed on polling, component-name filtering, and further parser maintenance. Failures retain last incidents **without a status-feed stale marker/age limit** in model state. Inferred consequences: old outage light can persist after failed checks; an empty initial feed is not “known healthy.” [Endpoints](https://github.com/ThiloReintjes/tinybar/blob/79cb32f7e71eacb9e8ce45508dd00fac26a08d53/Sources/TinybarCore/Status/Incident.swift#L51-L102), [retention](https://github.com/ThiloReintjes/tinybar/blob/79cb32f7e71eacb9e8ce45508dd00fac26a08d53/Sources/Tinybar/AppModel.swift#L201-L216).
- Forecast deliberately stores no rate history: average used share since `reset − duration`, suppressed during first 5% of window and for missing/expired reset or 0/100% use. This is a linear assumption about future behavior, not a provider prediction. Auto-selection based on that estimate is not simply “lowest percentage.” [Forecast](https://github.com/ThiloReintjes/tinybar/blob/79cb32f7e71eacb9e8ce45508dd00fac26a08d53/Sources/TinybarCore/LimitForecast.swift#L3-L43), [Auto policy](https://github.com/ThiloReintjes/tinybar/blob/79cb32f7e71eacb9e8ce45508dd00fac26a08d53/Sources/Tinybar/AppModel.swift#L396-L414).
- Alerts: only account-wide 5h/weekly windows; 90%/95% once per reset cycle, reset notification only after a near-exhausted cycle. No monthly or model-specific alerts. Notifications authorization is requested at start once; launch-at-login registration defaults on first run. Notification permission is used for **both limit and release notifications** even though setting label mentions nearly-used limits. [Planner](https://github.com/ThiloReintjes/tinybar/blob/79cb32f7e71eacb9e8ce45508dd00fac26a08d53/Sources/TinybarCore/LimitAlerts.swift#L3-L56), [notifier](https://github.com/ThiloReintjes/tinybar/blob/79cb32f7e71eacb9e8ce45508dd00fac26a08d53/Sources/Tinybar/Notifier.swift#L13-L42), [startup](https://github.com/ThiloReintjes/tinybar/blob/79cb32f7e71eacb9e8ce45508dd00fac26a08d53/Sources/Tinybar/AppModel.swift#L82-L89), [login default](https://github.com/ThiloReintjes/tinybar/blob/79cb32f7e71eacb9e8ce45508dd00fac26a08d53/Sources/Tinybar/Settings.swift#L31-L53), [setting label](https://github.com/ThiloReintjes/tinybar/blob/79cb32f7e71eacb9e8ce45508dd00fac26a08d53/Sources/Tinybar/PopoverView.swift#L913-L919).
- Update checking is daily unauthenticated GitHub API, retry hourly on failure, persisted across launches. User clicks update (not silent installation). Homebrew installs detected by standard-prefix Caskroom symlinks; otherwise opens release page. Custom updater fetches the tap and **hard-resets it to upstream**, prefetches ZIP, checks listed version matches, then child shell waits for app exit, upgrades and reopens; failure log/marker survives relaunch. No Sparkle dependency, but bespoke shell/lifecycle/error cases replace it. [Schedule](https://github.com/ThiloReintjes/tinybar/blob/79cb32f7e71eacb9e8ce45508dd00fac26a08d53/Sources/TinybarCore/Updates/ReleaseCheck.swift#L14-L27), [retry logic](https://github.com/ThiloReintjes/tinybar/blob/79cb32f7e71eacb9e8ce45508dd00fac26a08d53/Sources/TinybarCore/Updates/ReleaseCheck.swift#L61-L92), [installer](https://github.com/ThiloReintjes/tinybar/blob/79cb32f7e71eacb9e8ce45508dd00fac26a08d53/Sources/Tinybar/Updater.swift#L97-L182).
- **Quiet updates are not established:** six release entries were returned between Oct 23 and Nov 1 (0.6.0, 0.6.1, 0.6.2, 0.6.3, 0.7.0, 0.8.0). Most recent release adds a provider. Security policy supports latest release only; settings have no independent update-check/update-notification switch. This does not prove future cadence, but Tinybar is not evidence that a small native app avoids frequent feature releases. [Live release list](https://api.github.com/repos/ThiloReintjes/tinybar/releases?per_page=8), [latest release](https://github.com/ThiloReintjes/tinybar/releases/tag/v0.8.0), [security support](https://github.com/ThiloReintjes/tinybar/blob/79cb32f7e71eacb9e8ce45508dd00fac26a08d53/SECURITY.md#L12-L14), [settings](https://github.com/ThiloReintjes/tinybar/blob/79cb32f7e71eacb9e8ce45508dd00fac26a08d53/Sources/Tinybar/PopoverView.swift#L913-L929).
- **Docs are not the complete network contract:** SECURITY.md says “exactly five places” and treats any other destination as bug, but actual code also calls GitHub and provider status domains (README correctly lists these). Treat as a documentation inconsistency, not evidence of exfiltration. [Security assertion](https://github.com/ThiloReintjes/tinybar/blob/79cb32f7e71eacb9e8ce45508dd00fac26a08d53/SECURITY.md#L33-L36), [release request](https://github.com/ThiloReintjes/tinybar/blob/79cb32f7e71eacb9e8ce45508dd00fac26a08d53/Sources/TinybarCore/Updates/ReleaseCheck.swift#L14-L22), [status sources](https://github.com/ThiloReintjes/tinybar/blob/79cb32f7e71eacb9e8ce45508dd00fac26a08d53/Sources/TinybarCore/Status/Incident.swift#L64-L94), [README correction](https://github.com/ThiloReintjes/tinybar/blob/79cb32f7e71eacb9e8ce45508dd00fac26a08d53/README.md#L90-L91).

#### Tests and current issue reports

- Tests target **TinybarCore**, not the app target. Inspected tests include provider parsing/units, replay/dedup/rewrite/recovery, pricing cache, forecast/alert logic, cross-origin credential redirect rejection, original DB/WAL preservation, Keychain-denial memoization and child-process deadline/cleanup. This is meaningful defensive coverage, but not evidence of UI/lifecycle end-to-end reliability. CI config builds/tests/bundles on `macos-15`; no runtime CI results were audited and no tests were run in this research. ### Inferences

#### Acceptable omissions if they match the user's needs

- **No first-party login/refresh management:** lowers credential-rotation contention and auth lifecycle ownership; accept explicit stale state when official client must renew. CLI delegation must still be considered a runtime/version/refresh dependency. [ADR](https://github.com/ThiloReintjes/tinybar/blob/79cb32f7e71eacb9e8ce45508dd00fac26a08d53/docs/adr/0001-read-only-credentials.md#L3-L12).
- **No Safari, no broad browser account chooser, no multi-account stacking:** potentially good focus for one account/provider; wrong if the user's workflow needs Safari-only sessions or multiple subscriptions. Safer still is no browser access at all if CLI auth suffices, avoiding crypto, DB snapshots and permission prompts. [Browser scope](https://github.com/ThiloReintjes/tinybar/blob/79cb32f7e71eacb9e8ce45508dd00fac26a08d53/docs/adr/0005-browser-cookie-consent.md#L1-L7), [account state](https://github.com/ThiloReintjes/tinybar/blob/79cb32f7e71eacb9e8ce45508dd00fac26a08d53/Sources/Tinybar/AppModel.swift#L18-L25), [request for stacking](https://github.com/ThiloReintjes/tinybar/issues/14).
- **Limits-only providers/Go-only OpenCode; daily aggregates/no raw transcript retention; fixed thresholds/cadence:** coherent product cuts, not inherently bugs. A limits-only new product could omit local parsing, DB migrations/backfills, price feeds, activity stats, benchmarks and plan-value forecasts altogether—large independent sources of complexity. Whether to do that is a discovery question, not a proposed implementation. [Go scope ADR](https://github.com/ThiloReintjes/tinybar/blob/79cb32f7e71eacb9e8ce45508dd00fac26a08d53/docs/adr/0009-opencode-go-only.md#L1-L13), [aggregate tradeoff](https://github.com/ThiloReintjes/tinybar/blob/79cb32f7e71eacb9e8ce45508dd00fac26a08d53/docs/adr/0003-daily-aggregates.md#L3-L11), [feature breadth](https://github.com/ThiloReintjes/tinybar/blob/79cb32f7e71eacb9e8ce45508dd00fac26a08d53/README.md#L47-L65).

#### Reliability gaps not justified merely by “smallness”

- Provenance without account identity, age-only freshness not represented, schema drift becoming “No limits,” history failures becoming empty/recent-looking output, status feed failures preserving incident state without freshness, and main-thread synchronous startup work are different from deliberately omitting another provider. They can undermine trust in core information. These are inferred risks from code, **not reproduced bugs or lag measurements**. [Snapshot/state](https://github.com/ThiloReintjes/tinybar/blob/79cb32f7e71eacb9e8ce45508dd00fac26a08d53/Sources/TinybarCore/Models.swift#L165-L187), [staleness definition](https://github.com/ThiloReintjes/tinybar/blob/79cb32f7e71eacb9e8ce45508dd00fac26a08d53/Sources/Tinybar/AppModel.swift#L6-L14), [history error handling](https://github.com/ThiloReintjes/tinybar/blob/79cb32f7e71eacb9e8ce45508dd00fac26a08d53/Sources/Tinybar/AppModel.swift#L279-L304).
- Permission/collection semantics should be explicit: Cursor's browser exception, background collection despite disabled quota provider, first-run login/notification defaults, update notifications sharing limit permission, and temporary whole-DB copies are material user-facing tradeoffs, not invisible implementation details. [Cursor behavior](https://github.com/ThiloReintjes/tinybar/blob/79cb32f7e71eacb9e8ce45508dd00fac26a08d53/Sources/TinybarCore/Cursor/CursorProvider.swift#L16-L43), [all-source ingest](https://github.com/ThiloReintjes/tinybar/blob/79cb32f7e71eacb9e8ce45508dd00fac26a08d53/Sources/TinybarCore/Usage/UsageStore.swift#L234-L251), [temporary copy](https://github.com/ThiloReintjes/tinybar/blob/79cb32f7e71eacb9e8ce45508dd00fac26a08d53/Sources/TinybarCore/Cookies/BrowserCookies.swift#L231-L259).

#### Reusable lessons, not a chosen specification

1. **Decide which question the app answers before selecting adapters:** “can I continue?”, “when does quota reset?”, “how much did this Mac use?”, and “was this subscription good value?” are different data products. Tinybar demonstrates how including all four rebuilds substantial complexity. [Feature scope](https://github.com/ThiloReintjes/tinybar/blob/79cb32f7e71eacb9e8ce45508dd00fac26a08d53/README.md#L47-L65).
2. **Keep a common quota model but retain source semantics:** provider, account confidence, source, used/remaining convention, reset, duration, fetched time and error/age are core trust information. Native rendering and a small common `LimitWindow`/`ProviderSnapshot` are useful; collapsing personal/team/model/estimated values into one indistinguishable percentage is not. [Common model](https://github.com/ThiloReintjes/tinybar/blob/79cb32f7e71eacb9e8ce45508dd00fac26a08d53/Sources/TinybarCore/Models.swift#L58-L83), [snapshot](https://github.com/ThiloReintjes/tinybar/blob/79cb32f7e71eacb9e8ce45508dd00fac26a08d53/Sources/TinybarCore/Models.swift#L158-L187), [team fallback](https://github.com/ThiloReintjes/tinybar/blob/79cb32f7e71eacb9e8ce45508dd00fac26a08d53/Sources/TinybarCore/Cursor/CursorUsageAPI.swift#L87-L103).
3. **Avoid work first:** coalesced polling, one in-flight pass, per-provider backoff, independent optional extras, incremental file offsets, retained last-good values and redraw-on-displayed-change are concrete patterns worth retaining if those sources are needed. They warrant measurement, not assumed performance numbers. [Refresh](https://github.com/ThiloReintjes/tinybar/blob/79cb32f7e71eacb9e8ce45508dd00fac26a08d53/Sources/Tinybar/AppModel.swift#L92-L198), [draw guard](https://github.com/ThiloReintjes/tinybar/blob/79cb32f7e71eacb9e8ce45508dd00fac26a08d53/Sources/Tinybar/StatusItemController.swift#L65-L96).
4. **Test against the failure surface:** fixture parsing is necessary but insufficient; preserve originals/WALs, test redirect refusal/denial/timeout/dead child cases, then validate real provider accounts and app sleep/wake/locked/offline/schema-change UI. Tinybar's boundary tests are reusable thinking; its OpenCode disclosure is a reminder not to confuse mock agreement with paid-account proof. [Boundary tests](https://github.com/ThiloReintjes/tinybar/blob/79cb32f7e71eacb9e8ce45508dd00fac26a08d53/Tests/TinybarCoreTests/ProviderBoundaryTests.swift#L34-L113), [OpenCode validation limit](https://github.com/ThiloReintjes/tinybar/blob/79cb32f7e71eacb9e8ce45508dd00fac26a08d53/docs/adr/0009-opencode-go-only.md#L15-L29).
5. **Small product scope and quiet maintenance are separate commitments:** fewer protocols/features reduce surfaces, but native Swift alone does not guarantee fewer releases, stable auth, clear numbers or good update behavior. A bespoke Homebrew updater is itself complexity; whether releases should notify at all is a product decision. [Updater](https://github.com/ThiloReintjes/tinybar/blob/79cb32f7e71eacb9e8ce45508dd00fac26a08d53/Sources/Tinybar/Updater.swift#L139-L182), [release history](https://github.com/ThiloReintjes/tinybar/releases).

### Gaps

**Questions for the user before architecture or UI decisions:**

- Which providers/products and subscription tiers are actually used? Which official clients and login methods? One account each, work/personal organizations, or stacked subscriptions?
- Which CodexBar numbers are confusing: used vs remaining, 5h vs weekly, model vs account, billing cost vs API-equivalent cost, local activity vs account usage, Auto indicator switching, or stale values?
- Is the essential decision “can I keep working / when can I resume,” or is local token/cost/project history genuinely useful? Is any history worth retaining after logs disappear?
- Do other devices, browsers or clients consume the same account limits? Must the app identify account/source and detect changes?
- Are CLI-only credentials acceptable? Is browser-cookie access acceptable with explicit consent, or out of scope? Is asking the official client to renew an expired login acceptable?
- How fresh must numbers be when hidden/open/on wake? What should remain visible offline, and after what age must it clearly become stale/unknown?
- What precisely feels laggy: opening the popover, login checks, background CPU, memory, initial imports, update installation or information changing underneath the user? Reproduce/measure that baseline rather than assume an app framework explains it.
- Are alerts wanted at all? Which thresholds/windows? Should model-specific or monthly exhaustion count? Should update checking and update notifications be separate or absent?
- Is one stable chosen provider/window preferable to a changing Auto aggregate? Is a forecast helpful or more confusing than authoritative remaining/reset data?
- What macOS versions/architectures and distribution/update constraints matter? Is Homebrew acceptable, and is a quietly manual release-page workflow enough?
