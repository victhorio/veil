# CodexBar evidence for a focused native macOS usage monitor

## 1. What was inspected, and what is the actual architecture and release state?

### Takeaway
CodexBar is already a native Swift/AppKit/SwiftUI application; “make it native” would not distinguish a replacement. The credible simplification is fewer supported authorities, data products, and refresh/UI states—not a language rewrite.

### Inferences
- The README's “Tiny,” “minimal UI” language describes positioning, not a measured resource footprint or current scope. The native architecture and many independent targets explain why “native” alone is an insufficient product hypothesis. Frequent releases mix feature additions, app-owned fixes, and provider compatibility changes; fewer features would remove some, not all, maintenance.
- Reusing protocol knowledge or narrowly selected parsers is materially different from depending on the whole Core package, which brings plugin, crypto, cookie, cross-platform, and accounting concerns. A new project should audit the exact copied portions and their notices rather than assuming the root MIT license covers every bundled asset/dependency. MIT grants no provider-service access contract or trademark rights.

### Gaps
- The installed CodexBar version, install origin, enabled features, update preferences, architecture, and actual user symptoms were deliberately not inspected. No claim here identifies the cause of this user's lag or breakage.
- No builds, package resolution, repository scripts, tests, signing operations, or app launches were executed.

## 2. How does Codex actually collect usage, and what do its numbers mean?

### Takeaway
The main paths are authenticated account-level server responses (PAT/OAuth) or structured Codex app-server RPC—not “count tokens from local logs to determine remaining subscription quota.” Browser dashboard enrichment and local cost estimation are separate products with different authority and coverage.

### Cited Findings
- **Auto order:** PAT → OAuth → CLI, skipping unavailable strategies; a selected managed workspace removes CLI from Auto because the CLI cannot receive CodexBar's selected workspace header. Explicit OAuth plans a native-owner CLI recovery step; explicit Web is separate. Network/server/decode errors do not generally trigger OAuth→CLI fallback; repairable credential failures/unauthorized can. [Strategy resolver](https://github.com/steipete/CodexBar/blob/897bff31731bb4b21b105f6e8bf4c32a8a8bf095/Sources/CodexBarCore/Providers/Codex/CodexProviderDescriptor.swift#L152-L174), [scoped explicit recovery](https://github.com/steipete/CodexBar/blob/897bff31731bb4b21b105f6e8bf4c32a8a8bf095/Sources/CodexBarCore/Providers/Codex/CodexProviderDescriptor.swift#L344-L378), [fallback classification](https://github.com/steipete/CodexBar/blob/897bff31731bb4b21b105f6e8bf4c32a8a8bf095/Sources/CodexBarCore/Providers/Codex/CodexProviderDescriptor.swift#L492-L528).
- Native credentials come from `$CODEX_HOME/auth.json`, default `~/.codex/auth.json`. PAT fields are `personal_access_token` or `personalAccessToken`. PAT first calls `https://auth.openai.com/api/accounts/v1/user-auth-credential/whoami`, then usage with that identity's `ChatGPT-Account-Id`, Bearer, CLI-derived User-Agent, and originator headers. [Credential file](https://github.com/steipete/CodexBar/blob/897bff31731bb4b21b105f6e8bf4c32a8a8bf095/Sources/CodexBarCore/Providers/Codex/CodexOAuth/CodexOAuthCredentials.swift#L97-L112), [PAT fields](https://github.com/steipete/CodexBar/blob/897bff31731bb4b21b105f6e8bf4c32a8a8bf095/Sources/CodexBarCore/Providers/Codex/CodexOAuth/CodexOAuthCredentials.swift#L221-L229), [PAT requests](https://github.com/steipete/CodexBar/blob/897bff31731bb4b21b105f6e8bf4c32a8a8bf095/Sources/CodexBarCore/Providers/Codex/CodexPAT/CodexPATUsageFetcher.swift#L18-L107).
- OAuth calls **GET `https://chatgpt.com/backend-api/wham/usage`**, Bearer plus optional `ChatGPT-Account-Id`, cache bypass, 30-second request timeout. Provider config can override the ChatGPT base URL. [Request](https://github.com/steipete/CodexBar/blob/897bff31731bb4b21b105f6e8bf4c32a8a8bf095/Sources/CodexBarCore/Providers/Codex/CodexOAuth/CodexOAuthUsageFetcher.swift#L379-L422), [URL resolution](https://github.com/steipete/CodexBar/blob/897bff31731bb4b21b105f6e8bf4c32a8a8bf095/Sources/CodexBarCore/Providers/Codex/CodexOAuth/CodexOAuthUsageFetcher.swift#L569-L638).
- **Token ownership is consequential:** the usage path rereads a missing/partially published native file up to twice, 50 ms apart; it does not redeem another application's rotating refresh token or write native `auth.json`. Native freshness uses JWT expiry with a five-minute margin, otherwise `last_refresh` older than eight days; stale external credentials fail closed. Owner CLI recovery is intentionally constrained rather than an arbitrary fallback. [Retries/ownership](https://github.com/steipete/CodexBar/blob/897bff31731bb4b21b105f6e8bf4c32a8a8bf095/Sources/CodexBarCore/Providers/Codex/CodexProviderDescriptor.swift#L394-L477), [freshness](https://github.com/steipete/CodexBar/blob/897bff31731bb4b21b105f6e8bf4c32a8a8bf095/Sources/CodexBarCore/Providers/Codex/CodexOAuth/CodexOAuthCredentials.swift#L51-L61), [external sources opt-in](https://github.com/steipete/CodexBar/blob/897bff31731bb4b21b105f6e8bf4c32a8a8bf095/docs/codex.md#L106-L116).
- JSON windows explicitly contain **`used_percent`, `reset_at`, `limit_window_seconds`**. Classify by actual duration, not array slot or plan name: 300 min = 5h, 10,080 min = weekly; current code also handles explicitly reported 43,200-min/30-day limits. Additional model limits are independent named windows. These percentages are allowance utilization, not “tokens used / universal token cap.” [Wire model](https://github.com/steipete/CodexBar/blob/897bff31731bb4b21b105f6e8bf4c32a8a8bf095/Sources/CodexBarCore/Providers/Codex/CodexOAuth/CodexOAuthUsageFetcher.swift#L161-L237), [normalizer](https://github.com/steipete/CodexBar/blob/897bff31731bb4b21b105f6e8bf4c32a8a8bf095/Sources/CodexBarCore/Providers/Codex/CodexRateWindowNormalizer.swift#L3-L52), [lane classification](https://github.com/steipete/CodexBar/blob/897bff31731bb4b21b105f6e8bf4c32a8a8bf095/Sources/CodexBarCore/Providers/Codex/CodexProviderDescriptor.swift#L240-L253).
- CLI starts **`codex -s read-only -a never app-server`** and exchanges structured messages: initialize → `account/rateLimits/read` → best-effort `account/read`; requests are serialized on the shared stdout stream; process shuts down after measurement. The normal quota path is not PTY `/status` scraping. The capture time is local `Date()`, and provenance labels RPC as localRPC (the code cannot prove an app-server response is freshly revalidated upstream). [RPC defaults/methods](https://github.com/steipete/CodexBar/blob/897bff31731bb4b21b105f6e8bf4c32a8a8bf095/Sources/CodexBarCore/UsageFetcher.swift#L1000-L1074), [measurement](https://github.com/steipete/CodexBar/blob/897bff31731bb4b21b105f6e8bf4c32a8a8bf095/Sources/CodexBarCore/UsageFetcher.swift#L1211-L1263).
- **Quota, credits, and money are not interchangeable.** OAuth credits carry remaining balance, availability, unlimited status, and potentially monthly cap metadata. A missing balance may require an account-scoped workspace balance request; the placeholder zero is explicitly marked unread, not spent. App OAuth also attempts `/wham/rate-limit-reset-credits`; this is inventory of reset grants, not token expenditure. [Credits mapping](https://github.com/steipete/CodexBar/blob/897bff31731bb4b21b105f6e8bf4c32a8a8bf095/Sources/CodexBarCore/Providers/Codex/CodexProviderDescriptor.swift#L531-L548), [workspace balance](https://github.com/steipete/CodexBar/blob/897bff31731bb4b21b105f6e8bf4c32a8a8bf095/Sources/CodexBarCore/Providers/Codex/CodexProviderDescriptor.swift#L573-L615), [reset-credit refresh](https://github.com/steipete/CodexBar/blob/897bff31731bb4b21b105f6e8bf4c32a8a8bf095/Sources/CodexBarCore/Providers/Codex/CodexProviderDescriptor.swift#L438-L489).
- Even a successful OAuth Auto fetch can conditionally invoke CLI **inside** monthly-credit enrichment (unscoped Auto + includeCredits + zero balance/no cap/no reset inventory), merging only a compatible identity's cap. Thus “OAuth source” is not an unconditional guarantee of zero subprocesses in Auto. [Conditional CLI enrichment](https://github.com/steipete/CodexBar/blob/897bff31731bb4b21b105f6e8bf4c32a8a8bf095/Sources/CodexBarCore/Providers/Codex/CodexProviderDescriptor.swift#L679-L712), [predicate](https://github.com/steipete/CodexBar/blob/897bff31731bb4b21b105f6e8bf4c32a8a8bf095/Sources/CodexBarCore/Providers/Codex/CodexProviderDescriptor.swift#L824-L845).
- Optional **OpenAI browser extras** are a separate post-provider refresh, not Auto's last quota fallback. Cookie-authenticated dashboard collection has API preflight plus optional WebKit page scrape; the latter hosts an almost-offscreen window at alpha 0.001 for hydration and polls readiness/DOM. Browser-account ownership must be authorized before attachment. [Refresh sequencing](https://github.com/steipete/CodexBar/blob/897bff31731bb4b21b105f6e8bf4c32a8a8bf095/Sources/CodexBar/UsageStore/UsageStore.swift#L838-L858), [explicit Web strategy](https://github.com/steipete/CodexBar/blob/897bff31731bb4b21b105f6e8bf4c32a8a8bf095/Sources/CodexBarCore/Providers/Codex/CodexWebDashboardStrategy.swift#L11-L57), [WebKit host](https://github.com/steipete/CodexBar/blob/897bff31731bb4b21b105f6e8bf4c32a8a8bf095/Sources/CodexBarCore/OpenAIWeb/OpenAIDashboardFetcher.swift#L1-L46), [DOM readiness loop](https://github.com/steipete/CodexBar/blob/897bff31731bb4b21b105f6e8bf4c32a8a8bf095/Sources/CodexBarCore/OpenAIWeb/OpenAIDashboardFetcher+PageScrape.swift#L34-L139).
- **Displayed availability can be derived, not raw:** Codex's icon projection forces the session window to fully used when weekly remaining is zero and its reset has not elapsed. Read the source label/window labels before interpreting a screenshot as a raw provider reading. [Projection](https://github.com/steipete/CodexBar/blob/897bff31731bb4b21b105f6e8bf4c32a8a8bf095/Sources/CodexBarCore/Providers/Codex/CodexProviderDescriptor.swift#L204-L253).
- Local Codex accounting scans known session/archived-session JSONL paths and stores incremental accounting separately. Token-count events include last/cumulative token usage; estimates use prices, request/tier/deduplication evidence. A scanned `.jsonl` becoming `.jsonl.zst` can retain old cached coverage, but compressed files never previously seen as plaintext are not automatically backfilled. This is **local API-equivalent cost**, not complete account spend or subscription charges. [Coverage/archives](https://github.com/steipete/CodexBar/blob/897bff31731bb4b21b105f6e8bf4c32a8a8bf095/docs/codex.md#L374-L430), [paths and estimates](https://github.com/steipete/CodexBar/blob/897bff31731bb4b21b105f6e8bf4c32a8a8bf095/docs/codex.md#L432-L456), [actual token JSON parser](https://github.com/steipete/CodexBar/blob/897bff31731bb4b21b105f6e8bf4c32a8a8bf095/Sources/CodexBarCore/Vendored/CostUsage/CostUsageScanner.swift#L3815-L3841).

### Inferences
- For quota-only monitoring, the reusable discovery is endpoint/headers + credential owner/account scope + window semantics + typed failure behavior. Local token/cost parsing cannot substitute for server quota, especially across machines or clients.
- Excluding browser extras, credits purchasing, monthly-credit enrichment, account promotion, and local cost history would remove substantial machinery if the user does not need those data products. Some “extra” identity safeguards are correctness requirements, not gratuitous features.

### Gaps
- No authenticated request was made; endpoint availability, account entitlements, reset behavior, and freshness were not live-verified. Backend endpoints/RPC behavior must not be represented as a documented stable public API merely because upstream successfully integrates them.

## 3. How does Claude collection differ, and which boundaries matter?

### Takeaway
Claude has a much more permission-sensitive collection graph. Manual success does not establish background usability: credential ownership, Keychain consent, opaque CLI children, source selection, rate-limit gates, and a 15-minute CLI cache all affect what a scheduled refresh can actually do.

### Cited Findings
- Ambient **macOS app Auto** plans OAuth → CLI → Web; macOS CLI Auto plans Web → CLI, while the main Linux CLI pipeline can include OAuth. A selected token account is an authority boundary: OAuth/web/admin credentials route only to their own source, and malformed selection does not fall through to an ambient account. Ambient Admin key in Auto selects Admin API instead of consumer quota. [Planner](https://github.com/steipete/CodexBar/blob/897bff31731bb4b21b105f6e8bf4c32a8a8bf095/Sources/CodexBarCore/Providers/Claude/ClaudeSourcePlanner.swift#L170-L209), [account/admin routing](https://github.com/steipete/CodexBar/blob/897bff31731bb4b21b105f6e8bf4c32a8a8bf095/Sources/CodexBarCore/Providers/Claude/ClaudeProviderDescriptor.swift#L292-L324), [platform planning inputs](https://github.com/steipete/CodexBar/blob/897bff31731bb4b21b105f6e8bf4c32a8a8bf095/Sources/CodexBarCore/Providers/Claude/ClaudeProviderDescriptor.swift#L374-L418).
- **OAuth credential sources:** explicit `CODEXBAR_CLAUDE_OAUTH_TOKEN` override; in-process memory/CodexBar-owned profile cache; profile credentials file (default `~/.claude/.credentials.json`); consent/policy-gated repair from Claude Code's `Claude Code-credentials` Keychain item. `mcpOAuth` alone is not the subscription credential. Source order includes cache outage and expired-record recovery exceptions; it is not “choose whichever token expires latest.” [Environment key](https://github.com/steipete/CodexBar/blob/897bff31731bb4b21b105f6e8bf4c32a8a8bf095/Sources/CodexBarCore/Providers/Claude/ClaudeOAuth/ClaudeOAuthCredentials.swift#L13-L27), [actual loader](https://github.com/steipete/CodexBar/blob/897bff31731bb4b21b105f6e8bf4c32a8a8bf095/Sources/CodexBarCore/Providers/Claude/ClaudeOAuth/ClaudeOAuthCredentials.swift#L336-L489), [credential docs](https://github.com/steipete/CodexBar/blob/897bff31731bb4b21b105f6e8bf4c32a8a8bf095/docs/claude.md#L188-L211), [MCP-only tests](https://github.com/steipete/CodexBar/blob/897bff31731bb4b21b105f6e8bf4c32a8a8bf095/Tests/CodexBarTests/ClaudeOAuthTests.swift#L46-L83).
- OAuth request is **GET `https://api.anthropic.com/api/oauth/usage?cedar_ember=1`**, Bearer, `anthropic-beta: oauth-2025-04-20`, version-derived Claude CLI User-Agent, 30-second request/90-second resource timeouts, ephemeral/no-URL-cache transport. Certain 400/403 inventory-opt-in rejections retry the base endpoint, not a different credential. 429 honors Retry-After through a token-scoped gate. [Actual request/response handling](https://github.com/steipete/CodexBar/blob/897bff31731bb4b21b105f6e8bf4c32a8a8bf095/Sources/CodexBarCore/Providers/Claude/ClaudeOAuth/ClaudeOAuthUsageFetcher.swift#L60-L146).
- OAuth `five_hour`, `seven_day`, and model/scoped fields report **utilization = used percentage**, plus ISO8601 `resets_at`. Mapping assigns 300-minute and 10,080-minute windows, preserving missing data; primary can be a weekly window when five-hour is absent. OAuth extra usage `used_credits` and `monthly_limit` are divided by 100 into monetary units, not subscription-quota tokens. [Mapping](https://github.com/steipete/CodexBar/blob/897bff31731bb4b21b105f6e8bf4c32a8a8bf095/Sources/CodexBarCore/Providers/Claude/ClaudeUsageFetcher.swift#L955-L1041), [fixture proves 12.5 means used](https://github.com/steipete/CodexBar/blob/897bff31731bb4b21b105f6e8bf4c32a8a8bf095/Tests/CodexBarTests/ClaudeOAuthTests.swift#L96-L114).
- **Web** uses `sessionKey` cookie, manual or imported browser/optional desktop session. It calls `https://claude.ai/api/organizations`, selects an explicitly requested organization or first chat-capable/non-API-only organization, then `/organizations/{id}/usage` (with reset-inventory opt-in and bounded retry). Best-effort overage/prepaid endpoints are `/overage_spend_limit` and `/prepaid/credits`. Cloudflare challenges are a distinct failure, not proof that authentication is missing. [Cookie/organization request](https://github.com/steipete/CodexBar/blob/897bff31731bb4b21b105f6e8bf4c32a8a8bf095/Sources/CodexBarCore/Providers/Claude/ClaudeWeb/ClaudeWebAPIFetcher.swift#L594-L617), [usage](https://github.com/steipete/CodexBar/blob/897bff31731bb4b21b105f6e8bf4c32a8a8bf095/Sources/CodexBarCore/Providers/Claude/ClaudeWeb/ClaudeWebAPIFetcher.swift#L624-L688), [organization selection](https://github.com/steipete/CodexBar/blob/897bff31731bb4b21b105f6e8bf4c32a8a8bf095/Sources/CodexBarCore/Providers/Claude/ClaudeWeb/ClaudeWebAPIFetcher.swift#L806-L827), [optional monetary requests](https://github.com/steipete/CodexBar/blob/897bff31731bb4b21b105f6e8bf4c32a8a8bf095/Sources/CodexBarCore/Providers/Claude/ClaudeWeb/ClaudeWebAPIFetcher.swift#L1237-L1286).
- **CLI** normally runs Claude interactively in a PTY, sends `/usage`, parses rendered text, then `/status` for identity only after valid usage. Main probe timeout defaults 20 seconds; startup-looking output can be retried. Captured percentages are normalized to “left,” then mapped back to canonical used percentage (`100 - left`); reset text is parsed into dates with a local observation time. [Probe](https://github.com/steipete/CodexBar/blob/897bff31731bb4b21b105f6e8bf4c32a8a8bf095/Sources/CodexBarCore/Providers/Claude/ClaudeStatusProbe.swift#L75-L106), [commands](https://github.com/steipete/CodexBar/blob/897bff31731bb4b21b105f6e8bf4c32a8a8bf095/Sources/CodexBarCore/Providers/Claude/ClaudeStatusProbe.swift#L140-L175), [mapping](https://github.com/steipete/CodexBar/blob/897bff31731bb4b21b105f6e8bf4c32a8a8bf095/Sources/CodexBarCore/Providers/Claude/ClaudeUsageFetcher.swift#L1196-L1243).
- PTY sessions are actor-serialized and account/config-root scoped. Defaults exit after each probe; keep-alive is a debug option. Probe configuration disables remote-control startup/user hooks for that child, uses a dedicated probe directory, and handles trust prompts only there; cleanup removes probe artifacts and session-owned caffeinate descendants. This machinery exists because “read usage by launching the provider” has side effects to contain. ## 4. What do refresh, concurrency, caches, stale states, menu opening, and wake handling actually do?

### Takeaway
CodexBar contains real coalescing, cancellation, off-main collection, and cache safeguards; “it blocks everything on the main thread” is not supported. There is nevertheless a large state graph, and several intentionally retained/suppressed measurements can look frozen without a stalled timer.

### Cited Findings
- Fresh-install default is Adaptive; migrated installations with no valid stored cadence fall back to legacy five minutes. Choices include Manual, 1/2/5/15/30 minutes, Adaptive, and separately consented agent-aware Adaptive. Plain Adaptive's policy uses interaction/power/thermal signals, not agent scanning. Current policy ranges 2–30 min: constrained 30, recent menu 2, warm 5, idle 15, long-idle 30; allowed recent local activity can cap slower agent-aware decisions at five minutes. [Cadence/policy](https://github.com/steipete/CodexBar/blob/897bff31731bb4b21b105f6e8bf4c32a8a8bf095/docs/refresh-loop.md#L10-L77).
- Timer tasks are detached utility work. Adaptive recomputes/sleeps after prior refresh completion. Fixed cadence anchors to the scheduled tick and skips missed ticks rather than launching an overlapping catch-up storm. A global `isRefreshing` guard coalesces provider batches; each enabled background provider gets a task, and status checks can run alongside it. Cost work and ordinary credits enrichment are scheduled separately. [Timers](https://github.com/steipete/CodexBar/blob/897bff31731bb4b21b105f6e8bf4c32a8a8bf095/Sources/CodexBar/UsageStore/UsageStore.swift#L926-L978), [fixed scheduling](https://github.com/steipete/CodexBar/blob/897bff31731bb4b21b105f6e8bf4c32a8a8bf095/Sources/CodexBar/UsageStore/UsageStore+AdaptiveRefresh.swift#L74-L115), [batch/fanout](https://github.com/steipete/CodexBar/blob/897bff31731bb4b21b105f6e8bf4c32a8a8bf095/Sources/CodexBar/UsageStore/UsageStore.swift#L767-L858).
- `UsageStore` state orchestration/publication is MainActor, but actual descriptor fetch runs in a child task explicitly off MainActor to avoid slow process/Keychain reads blocking menus. Per-provider request generations, predecessor waiting, and enablement/config/scope revisions reject stale publication after settings/account changes. [Execution boundary](https://github.com/steipete/CodexBar/blob/897bff31731bb4b21b105f6e8bf4c32a8a8bf095/Sources/CodexBar/UsageStore/UsageStore+Refresh.swift#L350-L390), [coalescing/generation](https://github.com/steipete/CodexBar/blob/897bff31731bb4b21b105f6e8bf4c32a8a8bf095/Sources/CodexBar/UsageStore/UsageStore+Refresh.swift#L96-L185).
- Root menu open records interaction and requests allowed agent-session work; it does **not synchronously fetch** quota. Menu construction/hosting/layout is MainActor. Delayed open-menu refresh ordinarily considers visible providers that are refreshing, error-stale, or missing; “refresh all on open” instead fans out every enabled provider, forces optional cost work, and defers OpenAI browser scrape until closure. Menu-originated automatic work is explicitly background/noninteractive. [Root opening](https://github.com/steipete/CodexBar/blob/897bff31731bb4b21b105f6e8bf4c32a8a8bf095/Sources/CodexBar/StatusItem/StatusItemController+Menu.swift#L66-L110), [delayed fetch](https://github.com/steipete/CodexBar/blob/897bff31731bb4b21b105f6e8bf4c32a8a8bf095/Sources/CodexBar/StatusItem/StatusItemController+Menu.swift#L1163-L1238), [plan](https://github.com/steipete/CodexBar/blob/897bff31731bb4b21b105f6e8bf4c32a8a8bf095/Sources/CodexBar/Menu/MenuOpenRefreshPlan.swift#L23-L42).
- **Surprising stale definition:** `UsageStore.isStale(provider:)` checks whether an error exists, **not snapshot age**. `hasSatisfiedUsageFetch` accepts a snapshot or known-unavailable limits. Thus an old retained snapshot without surfaced error does not necessarily cause an open-menu refresh. This is a code fact, not proof that every old snapshot is presented without an age label. [Definition/callers' retry predicate](https://github.com/steipete/CodexBar/blob/897bff31731bb4b21b105f6e8bf4c32a8a8bf095/Sources/CodexBar/UsageStore/UsageStore.swift#L706-L720).
- Error policy suppresses the first failure when prior data exists. Provider-specific preservation retains prior snapshots for recognized temporary failures, and Claude Auto/CLI paths have special retention. Some Claude timeout/rate-limit cases explicitly clear the error while retaining data. This trades transient-noise reduction against immediate failure visibility; original timestamps must carry freshness. [Consecutive failure gate](https://github.com/steipete/CodexBar/blob/897bff31731bb4b21b105f6e8bf4c32a8a8bf095/Sources/CodexBar/UsageStore/UsageStoreSupport.swift#L53-L72), [retention/suppression](https://github.com/steipete/CodexBar/blob/897bff31731bb4b21b105f6e8bf4c32a8a8bf095/Sources/CodexBar/UsageStore/UsageStore+Refresh.swift#L1400-L1453).
- Codex weekly-reset publication has its **own trust gate**. Initial near-zero weekly readings can require confirmation; invalid/backward boundaries preserve previous data. Delayed evidence has minimum age 60 s, maximum age 30 min, with plan/account/source/reset/credit prerequisites. This means successful HTTP can deliberately leave prior quota and time published. Tests explicitly cover unchanged-boundary publication on a later refresh and retaining prior surfaces. [Trust gate/constants](https://github.com/steipete/CodexBar/blob/897bff31731bb4b21b105f6e8bf4c32a8a8bf095/Sources/CodexBar/Providers/Codex/CodexWeeklyResetConfirmation.swift#L81-L149), [confirmation evidence](https://github.com/steipete/CodexBar/blob/897bff31731bb4b21b105f6e8bf4c32a8a8bf095/Sources/CodexBar/Providers/Codex/CodexWeeklyResetConfirmation.swift#L152-L203), [later-refresh regression test](https://github.com/steipete/CodexBar/blob/897bff31731bb4b21b105f6e8bf4c32a8a8bf095/Tests/CodexBarTests/CodexWeeklyResetPublicationTests.swift#L664-L755).
- Caches are not one thing: isolated HTTP transport (no URL cache, shared cookies, or credential storage for Codex); in-memory Claude CLI result TTL; profile OAuth cache; browser session cache; account-scoped retained usage/widget/history; incremental local-cost SQLite/JSON fragments/report memos; UI render/readiness caches. The tests assert two account HTTP requests remain distinct despite cacheable server responses. [HTTP isolation tests](https://github.com/steipete/CodexBar/blob/897bff31731bb4b21b105f6e8bf4c32a8a8bf095/Tests/CodexBarTests/CodexOAuthRequestTests.swift#L8-L53), [CLI cache](https://github.com/steipete/CodexBar/blob/897bff31731bb4b21b105f6e8bf4c32a8a8bf095/Sources/CodexBarCore/Providers/Claude/ClaudeCLIUsageSpawnThrottle.swift#L20-L44), [local memo mechanics](https://github.com/steipete/CodexBar/blob/897bff31731bb4b21b105f6e8bf4c32a8a8bf095/docs/claude.md#L660-L671), [UI readiness signature](https://github.com/steipete/CodexBar/blob/897bff31731bb4b21b105f6e8bf4c32a8a8bf095/Sources/CodexBar/StatusItem/StatusItemController+MenuRefreshScheduling.swift#L107-L155).
- Main-thread work remains real: menu models, readiness signatures over provider/history arrays, AppKit/SwiftUI layout, and WebKit operations. Local cost quota projection has off-main warmup but explicitly allows synchronous computation if a card arrives first. Existing slow-menu diagnostics use 150 ms and chart-render 50 ms thresholds; their presence is instrumentation, not proof those thresholds are exceeded on this Mac. [UI signature](https://github.com/steipete/CodexBar/blob/897bff31731bb4b21b105f6e8bf4c32a8a8bf095/Sources/CodexBar/StatusItem/StatusItemController+MenuRefreshScheduling.swift#L107-L155), [projection warmup](https://github.com/steipete/CodexBar/blob/897bff31731bb4b21b105f6e8bf4c32a8a8bf095/Sources/CodexBar/UsageStore/UsageStore+TokenCost.swift#L310-L317), [diagnostic thresholds](https://github.com/steipete/CodexBar/blob/897bff31731bb4b21b105f6e8bf4c32a8a8bf095/Sources/CodexBar/StatusItem/StatusItemController+MenuInteractionRefresh.swift#L5-L82).

### Inferences
- Plausible, **unmeasured** hazards: browser SPA hydration/DOM churn; full CLI startup and rendered-TUI parsing; many per-feature timers and retained projections; all-enabled-provider/status fanout; cache/suppression/trust-gate interactions; MainActor menu layout/chart/signature work. Fewer enabled providers/features should reduce possible work, but this analysis establishes neither CPU/RAM figures nor causality.
- The largest reliability simplification may be “one current snapshot and one visible failure/freshness state per explicitly chosen account,” not merely fewer rows in the same existing menu model.

### Gaps
- **Wake handling:** scoped searches across `Sources/CodexBar` and `Sources/CodexBarCore` for didWake/willSleep/workspace sleep-wake notifications found no dedicated quota refresh-on-wake observer. Timer code uses Swift `Task.sleep`, and fixed scheduling uses ContinuousClock/skips overdue ticks. This is a bounded negative source finding, not proof about every helper/framework or live resume behavior. No sleep/wake test was run. [Inspected timer implementation](https://github.com/steipete/CodexBar/blob/897bff31731bb4b21b105f6e8bf4c32a8a8bf095/Sources/CodexBar/UsageStore/UsageStore+AdaptiveRefresh.swift#L74-L115), [adaptive timer](https://github.com/steipete/CodexBar/blob/897bff31731bb4b21b105f6e8bf4c32a8a8bf095/Sources/CodexBar/UsageStore/UsageStore.swift#L926-L953).
- Tests were **read, not run**. Useful follow-up evidence fixtures: CodexOAuthRequestTests, ClaudeOAuthTests, ClaudeSourcePlannerTests, CodexWeeklyResetPublicationTests, MenuOpenRefreshPlanTests, AdaptiveRefreshTimerTests. They establish intended contracts; they do not prove live provider behavior or runtime performance.

## 6. What smaller architecture is worth discussing—not yet committing to?

### Takeaway
A plausible direction is a quota-first native status item with explicitly selected sources and visible freshness. This is a hypothesis for interviewing the user, not a settled implementation plan, provider choice, feature commitment, or performance claim.

### Cited Findings
- Existing native app and menu infrastructure demonstrate that SwiftUI plus AppKit is sufficient; the opportunity is to reduce the state/product surface. Existing request-generation guards and provider off-main fetch boundaries are useful correctness principles even if the large generic provider framework is not reused. [Native UI](https://github.com/steipete/CodexBar/blob/897bff31731bb4b21b105f6e8bf4c32a8a8bf095/Sources/CodexBar/StatusItem/StatusItemController.swift#L1-L43), [publication guards](https://github.com/steipete/CodexBar/blob/897bff31731bb4b21b105f6e8bf4c32a8a8bf095/Sources/CodexBar/UsageStore/UsageStore+Refresh.swift#L119-L185), [off-main fetch](https://github.com/steipete/CodexBar/blob/897bff31731bb4b21b105f6e8bf4c32a8a8bf095/Sources/CodexBar/UsageStore/UsageStore+Refresh.swift#L372-L390).
- Current data modeling proves the need for explicit measured usage direction, reset/date/duration, source/account identity, optional fields, and observation time—not arbitrary monthly token estimates inferred from plan names. [RateWindow model](https://github.com/steipete/CodexBar/blob/897bff31731bb4b21b105f6e8bf4c32a8a8bf095/Sources/CodexBarCore/UsageFetcher.swift#L3-L47), [Codex wire fields](https://github.com/steipete/CodexBar/blob/897bff31731bb4b21b105f6e8bf4c32a8a8bf095/Sources/CodexBarCore/Providers/Codex/CodexOAuth/CodexOAuthUsageFetcher.swift#L213-L237), [Claude mapping](https://github.com/steipete/CodexBar/blob/897bff31731bb4b21b105f6e8bf4c32a8a8bf095/Sources/CodexBarCore/Providers/Claude/ClaudeUsageFetcher.swift#L965-L1018).

### Inferences
- **Architecture hypothesis:** one small native app; one status item/popover; adapters only for providers/accounts the user confirms; one explicitly chosen authority per account, with user-visible repair rather than automatic cross-account/browser fallback. A small refresh coordinator owns one in-flight request per account, timeout/cancellation/generation checks, Retry-After/backoff, and one cached last-good snapshot. Collection/decoding stays off MainActor; UI receives immutable snapshots.
- **Domain hypothesis:** provider + stable account/workspace key + measuredAt/source + a list of named quota windows (`usedPercent`, actual duration, reset date, availability), with money/tokens a separate optional data product. Freshness is computed from measurement age independently of error state; retain last-good data with an unmistakable age/error indication instead of relabeling cached success as fresh. “Checking” and “updated” are separate events. Do not claim a local receipt time is server measurement time.
- **Refresh hypothesis:** launch and modest fixed background polling, manual refresh, async stale-on-open refresh, and one debounced wake-triggered refresh if old. Menu opens immediately from cache; no synchronous network/disk/history scan at open. One scheduler, not agent activity scanning, until a concrete need appears. Proposed intervals remain a user decision; no benchmark supports a specific energy/freshness tradeoff yet.
- **Scope hypothesis:** omit local cost scans, browser automation/import, account switching, plugins, charts, sync, server/CLI, widgets, animation and notifications initially unless the user identifies a reason. If no reliable permitted source can serve an account, show that limitation rather than adding invisible machinery. A no-browser/no-CLI target may be impossible for a particular user's auth setup; decide after their constraints are known.
- **Questions for the next discussion:**
  1. Which providers are actually used, and are these subscription quotas, API billing accounts, or both? Codex/Claude were researched because requested—not assumed to be the whole requirement.
  2. How many accounts/workspaces? Must the monitor follow another app's active account, independently pin one, display several, or switch credentials? Is usage from other devices important?
  3. What must be visible without clicking: remaining percent, used percent, session vs weekly bottleneck, reset countdown, account name, or a simple warning? Should derived “effective blocked” state ever replace raw window values?
  4. Does the user want money/tokens? If yes, server-billed spend, prepaid balance, monthly cap, or explicitly local API-equivalent estimate? Which are confusing today?
  5. What age is acceptable while coding/idle/after wake? Is a five-minute or fifteen-minute old value useful if clearly labeled? Does “Refresh” mean attempt now or guarantee a new remote measurement?
  6. Which credential authority and recovery policy are acceptable: reuse local CLI token read-only, monitor-owned login, manually supplied session, explicit owner-CLI launch? May background work invoke a CLI, prompt Keychain, inspect browsers, or read transcripts? No such permission is implied by this research.
  7. What happens on auth failure/offline/partial model failure: keep old values with age, hide numbers, or show an alert? Which is least misleading for this user?
  8. Is current annoyance mainly update prompts, auto-installs, bugs after updates, visual scope, or actual CPU/energy/menu latency? What concrete event would distinguish those? What release/install policy would the user prefer?
  9. Minimum macOS version, Intel support, distribution/signing expectations, and willingness to accept explicit manual reauthentication rather than complex automatic repair?

### Gaps
- This hypothesis has not been validated with the user or implemented. Simplicity cannot justify incorrectly mixing account scopes, hiding stale data, or treating missing quota as zero.
